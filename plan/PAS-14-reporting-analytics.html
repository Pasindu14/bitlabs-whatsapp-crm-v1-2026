Context & Data Availability

All three analytics pillars read from tables that are already populated by the running pipeline. No new DB columns or migrations are needed for 9.1 and 9.2. Phase 9.3 (cost) is limited to billable message counts by category because Meta's status webhooks do not include a dollar amount — only billable: bool and category: string. Estimating spend from published per-country rates is out of scope for this plan.

PRD itemData sourceKey fields already captured
9.1 Message metrics Messages table Status (Sent/Delivered/Read/Failed), Direction, CreatedAt, CampaignId
9.2 Campaign performance CampaignRecipients table CampaignId, Status (Queued/Sent/Delivered/Read/Failed/Skipped), ErrorCode
9.3 Cost analytics Messages table Billable (bool?), Category (string? marketing/utility/authentication/service), CreatedAt
9.3 scope note: Meta's pricing object in the status webhook contains billable and category only — no price amount. This plan delivers billable message counts per category, which is the correct foundation. A separate plan can add a configurable rate table (price per category × country) to derive estimated spend if needed later.

Decisions

TopicDecision
Feature location New vertical slice Features/Analytics/ in the API. Single controller, single service. No repository layer — all queries are read-only projections via EF Core.
Permission gate [RequirePermission("Analytics")] on all three endpoints. Company Admins already implicitly hold all permissions. Super-admin bypasses via IsSuperAdmin.
Date range param Optional ?from= and ?to= query params (ISO-8601 UTC). Default: last 30 days. Capped at 365 days server-side to prevent full-table scans.
Tenant isolation All three endpoints rely on the global EF Core query filter — no manual WHERE CompanyId. Super-admin calls use IgnoreQueryFilters + explicit ?companyId= param (existing pattern from other super-admin endpoints).
9.1 granularity Return totals + a daily breakdown (one row per calendar day in the range) for trend charts. Inbound and outbound split included.
9.2 endpoint Paginated list of campaigns with stats columns (total/sent/delivered/read/failed/skipped) so the frontend can render a sortable table. No charting needed for per-campaign stats — a table with color-coded delivery rate is sufficient.
9.3 grouping Group by Category (nullable — use "unknown" for rows where webhook has not arrived yet). Only Billable = true rows count toward cost; show Billable = false separately as a free-tier count.
Caching No caching in v1 — queries are fast on the indexed columns (CompanyId, CreatedAt, Status). Add Redis cache if query time exceeds 500 ms under production load.
Web route New protected route /analytics. Three sections on one page (tabs or scroll sections). Use Recharts (already installed) for the bar/line charts. No separate sub-pages needed.
Sidebar Add "Analytics" nav entry under the company section. Guard with usePermissions("Analytics") — same pattern used by other nav items.

Date range helper (shared)

private (DateTime from, DateTime to) ResolveRange(DateTime? from, DateTime? to)
{
    var end   = (to   ?? DateTime.UtcNow).Date.AddDays(1).AddTicks(-1);
    var start = (from ?? end.AddDays(-29).Date);
    if ((end - start).TotalDays > 365)
        start = end.AddDays(-365);
    return (start, end);
}

9.1 — Message metrics query

public async Task<MessageMetricsResponse> GetMessageMetricsAsync(
    DateTime? from, DateTime? to, CancellationToken ct)
{
    var (start, end) = ResolveRange(from, to);

    var messages = await _db.Messages
        .Where(m => m.CreatedAt >= start && m.CreatedAt <= end)
        .Select(m => new { m.Status, m.Direction, m.CreatedAt.Date })
        .ToListAsync(ct);

    return new MessageMetricsResponse
    {
        TotalSent      = messages.Count(m => m.Direction == MessageDirection.Outbound),
        TotalInbound   = messages.Count(m => m.Direction == MessageDirection.Inbound),
        TotalDelivered = messages.Count(m => m.Status == MessageStatus.Delivered),
        TotalRead      = messages.Count(m => m.Status == MessageStatus.Read),
        TotalFailed    = messages.Count(m => m.Status == MessageStatus.Failed),
        Daily = messages
            .GroupBy(m => m.Date)
            .OrderBy(g => g.Key)
            .Select(g => new DailyMessageStats
            {
                Date      = g.Key,
                Sent      = g.Count(m => m.Direction == MessageDirection.Outbound),
                Delivered = g.Count(m => m.Status == MessageStatus.Delivered),
                Read      = g.Count(m => m.Status == MessageStatus.Read),
                Failed    = g.Count(m => m.Status == MessageStatus.Failed),
                Inbound   = g.Count(m => m.Direction == MessageDirection.Inbound),
            }).ToList()
    };
}

9.2 — Campaign performance query

public async Task<PagedResult<CampaignPerformanceRow>> GetCampaignPerformanceAsync(
    int page, int pageSize, DateTime? from, DateTime? to, CancellationToken ct)
{
    var (start, end) = ResolveRange(from, to);

    var query = _db.Campaigns
        .Where(c => c.CreatedAt >= start && c.CreatedAt <= end)
        .Select(c => new CampaignPerformanceRow
        {
            CampaignId   = c.Id,
            Name         = c.Name,
            Status       = c.Status.ToString(),
            LaunchedAt   = c.LaunchedAt,
            TotalRecipients = c.Recipients.Count(),
            Sent         = c.Recipients.Count(r => r.Status != RecipientStatus.Queued
                                                  && r.Status != RecipientStatus.Skipped),
            Delivered    = c.Recipients.Count(r => r.Status == RecipientStatus.Delivered
                                                 || r.Status == RecipientStatus.Read),
            Read         = c.Recipients.Count(r => r.Status == RecipientStatus.Read),
            Failed       = c.Recipients.Count(r => r.Status == RecipientStatus.Failed),
            Skipped      = c.Recipients.Count(r => r.Status == RecipientStatus.Skipped),
        })
        .OrderByDescending(c => c.LaunchedAt);

    var total = await query.CountAsync(ct);
    var rows  = await query.Skip((page - 1) * pageSize).Take(pageSize).ToListAsync(ct);

    return new PagedResult<CampaignPerformanceRow>(rows, total, page, pageSize);
}

9.3 — Cost analytics query

public async Task<CostAnalyticsResponse> GetCostAnalyticsAsync(
    DateTime? from, DateTime? to, CancellationToken ct)
{
    var (start, end) = ResolveRange(from, to);

    var rows = await _db.Messages
        .Where(m => m.Direction == MessageDirection.Outbound
                 && m.CreatedAt >= start && m.CreatedAt <= end
                 && m.Billable != null)
        .GroupBy(m => new { m.Category, m.Billable })
        .Select(g => new { g.Key.Category, g.Key.Billable, Count = g.Count() })
        .ToListAsync(ct);

    return new CostAnalyticsResponse
    {
        TotalBillable = rows.Where(r => r.Billable == true).Sum(r => r.Count),
        TotalFree     = rows.Where(r => r.Billable == false).Sum(r => r.Count),
        ByCategory    = rows
            .GroupBy(r => r.Category ?? "unknown")
            .Select(g => new CategoryBreakdown
            {
                Category = g.Key,
                Billable = g.Where(r => r.Billable == true).Sum(r => r.Count),
                Free     = g.Where(r => r.Billable == false).Sum(r => r.Count),
            }).ToList()
    };
}

Endpoint contracts summary

GET /api/v1/analytics/messages Permission: Analytics

Query params: from, to (ISO-8601, optional).
Returns: totals (sent/inbound/delivered/read/failed) + daily array for the range.

GET /api/v1/analytics/campaigns Permission: Analytics

Query params: page, pageSize, from, to.
Returns: paginated list of campaigns with per-campaign delivery counts.

GET /api/v1/analytics/costs Permission: Analytics

Query params: from, to (optional).
Returns: total billable count, total free count, breakdown by pricing category.

CampaignPerformanceTable — delivery rate column

// Columns definition (excerpt)
{
  id: "deliveryRate",
  header: "Delivery rate",
  cell: ({ row }) => {
    const { delivered, totalRecipients } = row.original;
    const rate = totalRecipients > 0
      ? Math.round((delivered / totalRecipients) * 100)
      : 0;
    const color = rate >= 80 ? "text-green-600"
                : rate >= 50 ? "text-yellow-600"
                : "text-red-600";
    return <span className={`font-semibold ${color}`}>{rate}%</span>;
  }
}

Definition of Done

  • GET /api/v1/analytics/messages returns status totals + daily array; filtered by optional date range; blocked for users without Analytics permission.
  • GET /api/v1/analytics/campaigns returns paginated campaign rows with delivered/read/failed counts; delivery rate computable client-side.
  • GET /api/v1/analytics/costs returns billable + free counts broken down by Meta pricing category.
  • /analytics page renders three tabs — Messages (bar chart + stat cards), Campaigns (sortable table with delivery rate %), Costs (pie chart by category).
  • Date range picker on the page controls all three tabs simultaneously.
  • Analytics nav entry is visible only to users with the Analytics permission (Company Admins see it by default).
  • /my-subscription page route exists and is reachable from the sidebar.
  • Super-admin can view any company's analytics via the existing ?companyId= bypass pattern if needed (optional for v1 — can be added later).
