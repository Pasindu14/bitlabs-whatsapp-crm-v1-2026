Notifications Center

Warn users when a scheduled campaign won't have enough quota to send — at 3 days, 2 days, 1 day, and on the day itself — and notify immediately when a campaign fails.

Status Draft
Steps 6
Scope API + Hangfire + SignalR + Frontend
Related PAS-13 (quota guard)

Background & Problem

Scheduled campaigns fire at a future time via CampaignSchedulerJob (runs every minute). If a company's MessagesUsedThisPeriod grows between now and the scheduled fire time, the campaign may land on INSUFFICIENT_QUOTA_AT_FIRE_TIME and silently fail (PAS-13 adds that failure path). Users currently have no way to know this is about to happen.

Additionally, campaigns can fail for other reasons (poison handler, Meta API errors). There is no persistent notification system — only ephemeral SignalR chat events and Sonner toasts. We need:

  • A persisted Notification entity so messages survive page refreshes
  • A daily Hangfire job that scans upcoming scheduled campaigns and checks if quota will be sufficient
  • Hooks in the campaign failure path to emit a notification on failure
  • A frontend bell icon with unread count + notification panel

Notification Types

QUOTA_WARNING_3D
Scheduled campaign fires in ≤ 72 h, quota insufficient
QUOTA_WARNING_2D
Fires in ≤ 48 h, quota insufficient
QUOTA_WARNING_1D
Fires in ≤ 24 h, quota insufficient
QUOTA_WARNING_TODAY
Fires today (≤ 6 h), quota insufficient
CAMPAIGN_FAILED
Campaign hit a terminal failure (poison handler or fire-time quota fail)
Each warning type is issued at most once per campaign — idempotent via a unique DB index on (CampaignId, NotificationType). Later warnings supersede earlier ones in the UI (e.g., showing the most recent warning per campaign).

Step 3 — Background Job
Create QuotaWarningCheckerJob
📄 wa_api/wa_api/Features/Campaigns/Jobs/QuotaWarningCheckerJob.cs new 📄 wa_api/wa_api/Program.cs mod

Runs daily at 06:00 UTC. Scans all OneTime Scheduled campaigns across all companies:

public async Task RunAsync(CancellationToken ct)
{
    var now = DateTime.UtcNow;

    // Load all OneTime Scheduled campaigns that fire within the next 72 hours
    var upcoming = await _db.Campaigns
        .IgnoreQueryFilters()
        .Include(c => c.Company).ThenInclude(co => co.Subscription).ThenInclude(s => s.Plan)
        .Where(c => c.ScheduleType == ScheduleType.OneTime
                 && c.Status == CampaignStatus.Scheduled
                 && c.ScheduledAt > now
                 && c.ScheduledAt <= now.AddHours(72))
        .ToListAsync(ct);

    foreach (var campaign in upcoming)
    {
        var sub = campaign.Company.Subscription;
        if (sub is null || sub.Plan is null) continue;

        int remaining = sub.Plan.MonthlyMessageQuota - sub.MessagesUsedThisPeriod;
        int recipients = campaign.TotalRecipients > 0
            ? campaign.TotalRecipients
            : await ResolveDistinctRecipientCountAsync(campaign, ct);

        if (recipients <= remaining) continue;  // quota is fine — no warning needed

        var hoursUntil = (campaign.ScheduledAt!.Value - now).TotalHours;
        var type = hoursUntil switch
        {
            <= 6  => NotificationType.QuotaWarningToday,
            <= 24 => NotificationType.QuotaWarning1Day,
            <= 48 => NotificationType.QuotaWarning2Days,
            _     => NotificationType.QuotaWarning3Days,
        };

        var title = type == NotificationType.QuotaWarningToday
            ? $"Campaign \"{campaign.Name}\" sends today — quota insufficient"
            : $"Campaign \"{campaign.Name}\" scheduled in {(int)Math.Ceiling(hoursUntil / 24)} day(s) — quota low";

        var body = $"Needs {recipients:N0} messages, only {remaining:N0} remaining. " +
                   $"Upgrade your plan or reduce recipients before {campaign.ScheduledAt:d MMM HH:mm} UTC.";

        await _notificationService.CreateAsync(
            campaign.CompanyId, campaign.Id, type, title, body, ct);
    }
}

RecurringJob.AddOrUpdate<QuotaWarningCheckerJob>(

    "0 6 * * *");   // daily at 06:00 UTC
